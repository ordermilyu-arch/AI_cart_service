# AI Cart Service 포트폴리오 PDF 최신화 반영사항

기준 저장소: `ordermilyu-arch/AI_cart_service`  
기준 버전: V7 YOLOv8 로컬 모델 포함 버전  
작성일: 2026-09-10

이 문서는 기존 포트폴리오 PDF를 최신 구현 상태로 갱신할 때 반영할 내용을 정리한 것이다. 아래 내용은 GitHub 저장소에 포함된 코드와 모델을 기준으로 작성했으며, 실제로 아직 배포하지 않은 기능은 별도로 구분했다.

## 1. 프로젝트 소개 문구

**AI Cart Service는 카메라로 식재료를 인식해 장바구니를 자동으로 구성하고, 현재 장바구니 재료를 기준으로 레시피를 추천하는 스마트 카트 웹 서비스이다.**

사용자는 웹 브라우저에서 카메라 권한을 허용한 뒤 상품을 비추며, 서비스는 직접 학습한 YOLOv8 모델로 상품을 감지한다. 신뢰도와 연속 감지 조건을 통과한 상품만 장바구니에 반영한다.

## 2. 현재 구현 완료 기능

### 카메라·상품 인식

- 메인 화면과 전체화면 카메라 화면에서 브라우저 카메라 스트림을 표시한다.
- `getUserMedia()`로 노트북 또는 연결된 카메라 권한을 요청한다.
- 카메라 프레임을 약 **1.8초 간격**으로 JPEG 이미지로 변환해 Python 인식 서버에 전송한다.
- Python 백엔드는 직접 학습한 **V7 YOLOv8n 모델**으로 이미지를 추론한다.
- 상품 신뢰도가 **75% 이상**이고, **동일 상품이 2회 연속** 감지될 때만 장바구니에 1개를 추가한다.
- 직전에 장바구니에 등록한 상품과 같은 상품은 즉시 중복 등록하지 않는다.
- 인식이 확정되면 카메라 하단에 상품명과 장바구니 추가 안내 팝업을 표시한다.
- 메인 상단의 카메라 상태 버튼으로 디버그 패널을 열어 모델 원본 클래스명, 신뢰도, DB 상품 연결 결과, 연속 확인 횟수를 확인할 수 있다.
- `상품이 카메라에서 사라짐` UI를 통해 장바구니에서 1개를 뺄지 확인하는 팝업을 제공한다. 현재 이 동작은 사용자의 버튼 입력을 기준으로 하며, 객체가 화면에서 사라진 것을 자동 판정하는 기능은 구현 범위에 포함하지 않는다.

### 장바구니·결제 흐름

- 메인 우측 쇼핑 상태 패널에서 카트 내 상품 수, 개별 상품 수량과 금액, 최근 인식 상품을 표시한다.
- 장바구니 상세에서 상품별 수량 증가·감소, 상품 위치, 금액을 확인할 수 있다.
- 별도의 삭제 버튼을 누르면 “정말 제거할까요?” 확인 팝업을 표시한 뒤 상품을 삭제한다.
- 부가세를 별도로 더하지 않고, 한국 원화 상품 가격을 그대로 합산한다.
- 포장봉투 구매 체크 기능을 제공하며 봉투 가격은 **500원**이다.
- 바코드 기반 결제 화면과 결제 완료 화면을 제공한다.
- 결제 완료 버튼을 누르면 장바구니와 포장봉투 선택을 초기화하고 “이용해 주셔서 감사합니다” 안내를 표시한다.
- 실제 카드 결제·PG사·바코드 스캐너 연동은 포함하지 않은 UI 기반 데모 흐름이다.

### 레시피 추천·상세 화면

- 장바구니가 비어 있으면 추천 메뉴를 표시하지 않는다.
- 장바구니 재료가 하나 이상 있을 때만 레시피를 추천한다.
- 레시피별로 장바구니에 포함된 재료 수를 계산하고, **일치 재료 수가 많은 레시피를 우선** 정렬한다.
- 메인 화면의 추천 메뉴 카드를 누르면 요리 상세 화면으로 이동한다.
- 요리 상세 화면에서 메뉴 설명, 조리 시간, 간단한 조리 방법, 필요한 재료를 표시한다.

## 3. 데이터베이스 구성

| 파일 | 역할 | 주요 활용 기능 |
| --- | --- | --- |
| `ingredients.db` | 상품 데이터 | 상품명, 가격, 단위, 진열 위치, 보관 유형 |
| `recipes.db` | 레시피 데이터 | 메뉴 설명, 조리 시간, 재료 구성, 조리 방법 |

- 두 SQLite 데이터베이스가 저장소에 포함되어 있어 clone 후 별도 DB 설정 없이 실행할 수 있다.
- 상품 가격은 원화(KRW)로 표시된다.
- 인식된 모델 클래스명은 프론트엔드 별칭 표를 통해 DB의 한글 상품명으로 연결된다.

## 4. V7 로컬 YOLOv8 모델

### 최종 적용 모델

- 모델 구조: YOLOv8n
- 학습 장치: NVIDIA GeForce RTX 4060 Laptop GPU (CUDA)
- 학습 설정: 50 epochs, 이미지 크기 640 x 640
- 서비스 가중치: `backend/models/smart_cart.pt`
- 모델 크기: 약 6MB
- 외부 Roboflow API·API 키 없이 Python 백엔드에서 직접 모델을 로드한다.

### 인식 클래스와 서비스 상품 연결

| YOLO 클래스명 | 서비스 상품 |
| --- | --- |
| `apple` | 부사 사과 |
| `bread` | 우유 식빵 |
| `carrot` | 당근 |
| `egg` | 동물복지 계란 |
| `galic` | 깐마늘 |
| `l_onion` | 대파 |
| `onion` | 양파 |
| `raw_pork` | 돼지고기 앞다리살 |
| `shrimp` | 흰다리 새우 |
| `sliced_ham` | 슬라이스 햄 |

### V7 검증 성능

| 기준 | Epoch | Precision | Recall | mAP@50 | mAP@50:95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| mAP@50 최고 | 44 | 78.26% | 81.41% | **83.96%** | 71.13% |
| mAP@50:95 최고 | 49 | 73.53% | 86.73% | 83.27% | **72.06%** |

학습 데이터는 원본 이미지 그룹 기준 Train 620 / Validation 78 / Test 78로 구성했다. 원본 데이터셋과 중간 실험 모델은 공개 저장소에 포함하지 않고, 최종 V7 서비스 가중치 하나만 포함한다.

## 5. 시스템 구조

```text
브라우저 카메라
  ↓ 약 1.8초마다 JPEG 프레임 전송
React + Vite 프론트엔드
  ↓ POST /api/detect
Python HTTP API
  ↓ Ultralytics YOLOv8n
V7 smart_cart.pt 로컬 가중치
  ↓ 상품 클래스·신뢰도 반환
2회 연속 확인·DB 상품명 매핑
  ↓
장바구니 / 레시피 추천 / 결제 UI 갱신
```

## 6. 주요 API

| 메서드 | 경로 | 역할 |
| --- | --- | --- |
| GET | `/api/health` | 서버 및 모델 파일 상태 확인 |
| GET | `/api/products` | SQLite 상품 목록 조회 |
| GET | `/api/recipes` | 레시피 목록 조회 |
| GET | `/api/recipes/:id` | 레시피·재료·조리 정보 조회 |
| POST | `/api/recommendations` | 장바구니 재료 기반 추천 메뉴 조회 |
| POST | `/api/detect` | 카메라 JPEG 프레임 YOLO 추론 |

## 7. 재현과 배포 준비 상태

### Git clone 후 로컬 실행

- GitHub 저장소에 프론트엔드, 백엔드, DB, 최종 V7 모델, 학습·평가 스크립트, 실행 README가 포함돼 있다.
- clone한 사용자는 Python 의존성과 Node.js 패키지를 설치한 뒤 로컬에서 카메라 인식 기능을 실행할 수 있다.
- GPU가 없는 환경에서도 CPU로 동작할 수 있으나, 인식 반응은 GPU 환경보다 느릴 수 있다.
- API 키·Cloud Storage·Roboflow 계정은 필요하지 않다.

### 웹 배포 준비

- `backend/Dockerfile`: CUDA 기반 YOLOv8 백엔드 컨테이너 설정
- `cloudbuild.yaml`: GitHub push 기반 Cloud Build → Cloud Run GPU 자동 배포 설정
- `frontend/.env.example`: 배포 백엔드 주소를 위한 `VITE_API_BASE_URL` 예시

**현재 GitHub 저장소에는 배포 설정이 포함되어 있지만, 실제 외부 공개 웹 주소와 상시 운영 서버는 아직 연결되지 않은 상태이다.**

## 8. 공개 저장소 구성

```text
AI_cart_service/
├─ frontend/                 # React/Vite 스마트 카트 UI
├─ backend/                  # Python API와 YOLOv8 추론 모듈
│  └─ models/smart_cart.pt   # 최종 V7 서비스 가중치
├─ scripts/                  # 학습·데이터 분할·평가 소스
├─ docs/                     # 모델 기록, 배포 가이드, PDF 최신화 문서
├─ ingredients.db            # 상품 DB
├─ recipes.db                # 레시피 DB
├─ cloudbuild.yaml           # GPU 배포 자동화 설정
└─ README.md                 # 초보자용 clone·실행 안내
```

제외 항목: 원본 이미지 데이터셋, `BOX`, V8 등 중간 실험 가중치, 가상환경, `node_modules`, API 키 및 개인 환경 파일.

## 9. PDF에 넣을 핵심 성과 요약

1. 외부 API 호출형 모델 대신 자체 학습한 YOLOv8 V7 가중치를 서비스에 직접 연결했다.
2. 브라우저 카메라 입력을 주기적으로 전송하고, 75% 신뢰도·2회 연속 확인 규칙으로 중복 등록을 줄였다.
3. 상품·레시피 SQLite DB를 연결해 단순 객체 인식을 장바구니 관리와 개인화된 메뉴 추천 경험으로 확장했다.
4. React 프론트엔드와 Python 인식 API를 분리해 로컬 실행 및 컨테이너 기반 GPU 배포가 가능한 구조로 구성했다.
5. GitHub clone만으로 최종 모델을 포함한 로컬 데모 환경을 재현할 수 있도록 문서화했다.

## 10. PDF 표현 시 주의할 점

- “실시간 카메라 인식”은 브라우저 카메라 프레임을 약 1.8초 주기로 전송·분석하는 의미로 표현한다.
- “결제 기능”은 결제 UI와 장바구니 초기화 흐름이며, 실제 결제 대행사 연동은 아니다.
- “웹 배포”는 Docker·Cloud Build·Cloud Run 설정이 준비된 상태이며, 실제 배포 URL이 생성된 뒤에만 운영 중이라고 표현한다.
- V7 모델 성능은 위의 검증 지표와 함께 데이터셋 분할·평가 조건을 병기한다.
